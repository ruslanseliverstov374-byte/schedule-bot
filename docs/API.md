# API расписания Поволжского ГУФКСиТ

Как бот получает расписание: разбор сайта [timetable.unifirst.ru](https://timetable.unifirst.ru/)
и найденного у него публичного API. Документ нужен, чтобы понимать происходящее и уметь
починить бота, если вуз что-то поменяет.

---

## 1. Почему понадобился разбор

Сайт расписания — одностраничное JS-приложение (сборка Vite). На любой запрос сервер
отдаёт одну и ту же оболочку:

```html
<script type="module" crossorigin src="/assets/index-BxEAb22-.js"></script>
```

Значит, ни расписания, ни списка групп в HTML нет: всё подгружает скрипт. Поэтому бот
обращается не к странице, а к **API, которым пользуется сам сайт**.

> В архиве (Wayback Machine) сохранилась старая версия сайта на Drupal — там расписание
> было обычной HTML-таблицей с колонками `Пара | Дисциплина | Тип занятия | Аудитория |
> Преподаватель`. Сейчас так уже не работает, но структура данных та же.

## 2. Адрес и ключ

```
База:    https://api.unifirst.ru/api/v1
Заголовок: api-key: 777e5031c257a3d5ce7aa54aa56015cb
```

Ключ лежит **открытым текстом в JS-бандле сайта** (`assets/index-*.js`): фронтенд шлёт его
в каждом запросе. Это публичный ключ чтения, никаких персональных данных за ним нет.
Если вуз его сменит — ищите заново (раздел 6).

Без правильного заголовка сервер отвечает HTML-страницей 404 Drupal (а не JSON) — именно
по этому признаку видно, что ключ перестал работать. Бот в таком случае пишет в лог
`API вернул не JSON (возможно, изменился ключ доступа)`.

## 3. Эндпоинты

### 3.1 Список групп

```
GET /api/v1/groups?limit=500[&name=<подстрока>]
```

```json
{
  "data": [
    {"id": 1473, "name": "26281", "hasSubgroups": false, "subgroups": []},
    {"id": 1507, "name": "26281м", "hasSubgroups": false, "subgroups": []},
    {"id": 1474, "name": "26282", "hasSubgroups": false, "subgroups": []}
  ]
}
```

* Всего на момент разбора — **239 групп**.
* Названия — 5 знаков: 5 цифр (`26281`) либо 4 цифры + буква (`26281м`, `26110б`).
  Групп из 6 цифр не бывает, поэтому «262801» — это опечатка, бот сам подсказывает `26281`.
* `limit` до 1000; `name` фильтрует по подстроке без учёта регистра.
* Если у группы есть подгруппы (`hasSubgroups: true`), расписание запрашивается названием
  `«<группа> <подгруппа>»`, например `26281 бад`.

### 3.2 Расписание группы

```
GET /api/v1/timetable?title=<группа>[ <подгруппа>]&week=<ISO-неделя>&year=<год>
```

Пример: `/api/v1/timetable?title=26281&week=41&year=2026`

```json
{
  "meta": {"limit": 10, "count": 1, "week": 41, "year": 2026,
           "date_from": "2026-10-05", "date_to": "2026-10-11"},
  "data": [{
    "id": 128755, "title": "26281", "status": true,
    "group": {"id": 1473, "name": "26281"},
    "course": {"id": 7, "name": "1"},
    "subgroup": null, "facultet": null,
    "lessons": {
      "2026-10-05": {
        "label": "5 октября 2026, понедельник",
        "items": [
          {"para": 2, "title": "История России",
           "date": {"date": "05.10.2026", "time_start": "10:10", "time_end": "11:30"},
           "type": {"id": 8, "name": "пр."},
           "teachers": [{"id": 437, "name": "Фан-Юнг Г.Ю."}],
           "auditories": [{"id": 24, "name": "E703"}]}
        ]
      }
    }
  }]
}
```

Особенности, проверенные на живом API:

* `lessons` — словарь «дата (YYYY-MM-DD) → день», внутри `items` — пары.
* У пары есть всё нужное: номер пары, предмет, тип занятия, **точное время начала и конца**
  (расписание звонков искать не нужно), преподаватели и аудитории — списками.
* Известная группа без занятий на неделю отдаёт **одну запись с пустым `lessons: {}`**,
  а не пустой `data`. Неизвестная группа — `data: []`.
* Номера недель — ISO 8601 (`date.isocalendar()` в Python). Год в паре с неделей тоже
  ISO-год: на стыке декабря и января он может отличаться от календарного.
* Значения `week` и `year` сайт берёт из текущей даты, поэтому «текущая неделя» —
  это `iso_year_week(date.today())`.

### 3.3 Преподаватели

```
GET /api/v1/teachers?limit=20[&name=<подстрока>][&after=<курсор>|&before=<курсор>]
GET /api/v1/teachers/<id>/timetable?year=<год>&week=<неделя>
```

```json
{"data": [{"id": 437, "name": "Фан-Юнг Г.Ю."}],
 "pageInfo": {"startCursor": null, "endCursor": null, "hasNext": false, "hasPrev": false}}
```

Бот это использует частично: если открыть расписание преподавателя, можно сделать
его личную страницу в боте — задел на будущее.

## 4. Что бот делает с ответом

`schedule/unifirst.py` превращает вложенный JSON в плоский список пар:

```python
{"date": "2026-10-05", "para": 2, "start": "10:10", "end": "11:30",
 "subject": "История России", "type": "пр.",
 "teachers": ["Фан-Юнг Г.Ю."], "rooms": ["E703"], "uid": "a1b2c3d4e5f60718"}
```

* `uid` — отпечаток пары (дата + номер + время + предмет + тип + преподаватели +
  аудитории). По нему сравниваются версии.
* `digest(lessons)` — отпечаток всей недели: если он изменился, расписание поменялось.
* `diff_lessons(old, new)` — что именно изменилось: `added`, `removed` (и подсказка, какая
  пара стояла в том же слоте) — из этого бот собирает сообщение «⚠️ Расписание изменилось».

Вежливость к чужому серверу: бот кэширует ответы в SQLite, обновляет неделю не чаще, чем
раз в 20 минут (настраивается `--refresh-minutes`), и запрашивает только те группы, на
которые кто-то подписан.

## 5. Проверка API вручную

```bash
python -c "import sys; sys.path.insert(0,'.'); from schedule.unifirst import Unifirst, iso_year_week; from datetime import date; a=Unifirst(); print(len(a.groups()), 'групп'); y,w=iso_year_week(date.today()); print(a.timetable('26281', y, w)['meta'])"
```

Или полностью: `python bot.py --check` — покажет количество групп, пары группы 26281 на
текущую неделю и проверит разбор дат.

## 6. Если API изменился

Признаки: в логе `API вернул не JSON`, `HTTP 404 от API`, либо в боте «Занятий нет» на все
недели, хотя на сайте расписание есть.

Порядок восстановления (все инструменты уже в проекте):

1. Посмотреть, какие скрипты грузит сайт:
   `python tools/probe.py https://timetable.unifirst.ru/ --save data/shell.html`
2. Скачать новый бандл и вытащить из него адрес API и ключ:
   `python tools/probe.py https://timetable.unifirst.ru/assets/<имя-из-оболочки>.js --js`
   Ищите строки рядом с `api-key` — в бандле видно и базу API, и ключ.
3. Проверить эндпоинты как в разделе 5 и, если что-то поменялось, поправить константы
   `API_BASE` и `API_KEY` в `schedule/unifirst.py` (больше нигде адреса не зашиты).
4. Прогнать `python tests/simulate.py` — тесты работают на локальном моке и покажут, что
   логика бота не сломалась.

---

## 7. Правовая заметка

Бот использует тот же открытый API, что и публичный сайт расписания, не обходит
авторизацию, не собирает персональные данные и не создаёт заметной нагрузки. Ключ доступа
публикуется самим сайтом в его же JavaScript. Если вуз попросит прекратить — запрос
разумно выполнить.
