## Как это работает

```
GitHub (код)  →  Render Free (бот, вебхук)  →  Telegram
      ↑                    ↑                        ↑
keepalive.yml       Render проверяет          закреплённая копия базы
(каждые 5 мин)         /health                 в чате владельца
```

1. **Расписание** бот берёт тем же API, что и сайт `timetable.unifirst.ru`: предмет, тип
   занятия, точное время, аудитория, преподаватель. Никакого разбора HTML.
2. **Актуальность** — каждые 20 минут бот сам перезапрашивает текущую и следующую неделю
   для групп, на которые кто-то подписан, и сравнивает с сохранённой версией. Изменилось —
   подписчикам уходит сообщение с точными правками (что убрали, что добавили, где сменилась
   аудитория). Кнопка «🔄 Обновить» делает то же немедленно.
3. **Домашка** — общая база группы (любой добавляет, все видят, есть подтверждения «👍») плюс
   личные заметки. Формат ввода: `предмет | задание | срок`, срок понимается как `08.10`,
   `завтра`, `пн`, `через 3 дня`.
4. **Напоминания** — вечерний дайджест «что завтра» (по умолчанию 20:00 по Казани),
   предупреждение за 15/30/60 минут до пары, утреннее напоминание о дедлайнах.
5. **База не теряется**: каждые 30 минут бот отправляет сжатый снимок базы закреплённым
   сообщением в чат владельца и поднимает из него всё после перезапуска контейнера
   (у бесплатного Render диск стирается при каждом деплое).
6. **Сервис не засыпает**: раз в 5 минут GitHub обращается к `/health`.

## Если что-то случится

| Симптом | Что делать |
|---|---|
| Бот молчит | Открыть https://schedule-bot-frgz.onrender.com/health. Если 502 — сервис просыпается, подождать минуту |
| Пропали группы или ДЗ | Бот поднимет их из закреплённого сообщения при следующем запуске. Не удаляйте закреплённое сообщение в чате с ботом — это резервная копия |
| Нужно посмотреть логи | Render → сервис `schedule-bot` → **Logs** |
| Нужно перезапустить | Render → сервис `schedule-bot` → **Manual Deploy** → *Restart service* |
| В логе `API вернул не JSON` | Вуз сменил ключ доступа к API — инструкция в [API.md](API.md), раздел «Если API изменился» |
| Пропали напоминания | Проверить, что сервис жив (`/health`), и что в боте включены напоминания (⏰ Напоминания) |
| Не приходят изменения расписания | В боте: ⏰ Напоминания → «📣 Об изменениях» должно быть «вкл» |

## Что помнить про доступы

* **Токен бота** — в `token.txt` локально и в переменной `BOT_TOKEN` на Render (менять в двух
  местах). Если он «засветится»: @BotFather → `/mybots` → *API Token* → **Revoke**.
* **Токен GitHub** (`english-bot/data/github_token.txt`) — права `Contents` и `Workflows`,
  доступ к репозиторию `schedule-bot`, **истекает примерно 4 ноября 2026**. Для обновлений
  кода понадобится продлить срок или создать новый.
* **OWNER_ID** на Render = `1368878379` — чат, куда бот складывает копии базы.
* **Локальная копия бота остановлена** — иначе Telegram выдаёт
  `Conflict: terminated by other getUpdates request`. Не запускайте `run.bat` без
  необходимости: в облаке бот уже работает.
