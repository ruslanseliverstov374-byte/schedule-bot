> **Уже развёрнуто 5 октября 2026.** Бот ПГУФКСиТ работает на
> **https://schedule-bot-frgz.onrender.com** (имя `schedule-bot` на Render было занято,
> поэтому сервис получил суффикс `frgz`). Код — в репозитории
> [schedule-bot](https://github.com/ruslanseliverstov374-byte/schedule-bot),
> итоги и команды — в [HANDOVER.md](HANDOVER.md).
>
> Инструкция ниже нужна, если понадобится развернуть бота заново или поднять второй сервис.

Бот работает сам, без вашего компьютера и без карты: **GitHub (код) → Render Free (бот,
вебхук) → Telegram**, а пинг каждые 5 минут не даёт бесплатному сервису заснуть.
Ровно по этой схеме уже работает бот английского языка.

```
GitHub ──────────► Render Free ──────────► Telegram
   ▲                    │                     ▲
   │                    │ /health             │ вебхук
keepalive.yml     Render сам проверяет    сообщения приходят сразу
(раз в 5 минут)   и держит сервис живым
                       │
                  закреплённое сообщение в чате владельца = копия базы
```

## Два бота в одном сервисе (ПГУФКСиТ + КГАСУ)

Бесплатный тариф Render считает часы работы на аккаунт, поэтому **один сервис
обслуживает оба вуза**: внутри контейнера первый бот принимает сообщения вебхуком
(он же отдаёт `/health`), второй работает обычным опросом Telegram.

Что для этого нужно — одна дополнительная переменная в сервисе `schedule-bot`:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен бота Поволжского ГУФКСиТ |
| `BOT_TOKEN_KGASU` | токен бота КГАСУ (если её нет — запустится только первый бот) |
| `OWNER_ID` | ваш Telegram ID: в чаты с каждым ботом пойдут копии их баз |

Точка входа `start.py` сама выбирает режим: есть `BOT_TOKEN_KGASU` — запускаются оба
бота (`multi.py`), нет — обычный одиночный бот. Базы у ботов раздельные
(`data/bot.db` и `data/kgasu.db`), резервные копии — в своих чатах, друг другу не мешают.

Проверить, что второй бот поднялся:

```powershell
python tools/watch_kgasu_cloud.py     # ждёт 409 Conflict — признак живого опроса
```

Типичная ошибка при настройке: в значение переменной попадает текст-подсказка
(например «новый токен бота КГАСУ») вместо самого токена — бот при этом не стартует,
а сервис остаётся «здоровым», потому что первый бот продолжает работать.

## Что нужно

* аккаунт **GitHub** (у вас уже есть);
* аккаунт **Render** — регистрация через GitHub, карта не нужна;
* токен бота от @BotFather и **ваш Telegram ID** (бот покажет его по команде `/whoami`).

## Шаг 1. Репозиторий с кодом

Код уже должен быть в отдельном репозитории GitHub (например `schedule-bot`).
Если его ещё нет — пришлите разработчику ссылку на аккаунт, он зальёт.

Проверить, что ничего лишнего не уехало в репозиторий, можно так:

```powershell
cd schedule-bot
git status --short          # token.txt, .env, data/, logs/ быть не должно
```

---

## Шаг 2. Создание сервиса на Render

1. Откройте [dashboard.render.com](https://dashboard.render.com) и войдите через GitHub.
2. **New +** → **Blueprint**.
3. Выберите репозиторий с ботом расписания → **Connect**.
4. Render увидит файл `render.yaml` и предложит создать сервис `schedule-bot`
   (план **Free**, регион Frankfurt, проверка `/health`). Нажмите **Apply**.
5. В открывшемся окне заполните переменные:
   * `BOT_TOKEN` — токен от @BotFather;
   * `OWNER_ID` — ваш Telegram ID (бот покажет его по `/whoami`). В этот чат бот будет
     складывать закреплённую копию базы.
6. **Create** и подождите 2–5 минут: Render соберёт Docker-образ и запустит бота.

Адрес сервиса будет вида `https://schedule-bot.onrender.com` (точный покажет панель).
Бот сам увидит его в переменной `RENDER_EXTERNAL_URL`, включит вебхук и начнёт принимать
сообщения мгновенно — настраивать ничего не нужно.

## Шаг 3. Проверка

```powershell
# health-check: должно вернуться ok
curl https://schedule-bot.onrender.com/health

# страница состояния: пользователи, группы, кэш расписания
start https://schedule-bot.onrender.com/
```

Дальше напишите боту `/start` в Telegram — он попросит группу и покажет расписание.
Если бот молчит больше минуты — откройте в панели Render раздел **Logs** и посмотрите
последние строки.

---

## Шаг 4. Пинг, чтобы сервис не засыпал

В репозитории уже лежит `.github/workflows/keepalive.yml`: каждые 5 минут GitHub
обращается к `/health`. Осталось указать адрес сервиса:

1. GitHub → ваш репозиторий → **Settings** → **Secrets and variables** → **Actions** →
   вкладка **Variables** → **New repository variable**.
2. Имя: `BOT_URL`, значение: `https://schedule-bot.onrender.com` → **Add variable**.
3. Проверить: вкладка **Actions** → workflow `keepalive` → **Run workflow**;
   в логе должно быть `GET .../health -> 200`.

> GitHub отключает расписания после 60 дней без активности в репозитории. Чтобы это не
> стало сюрпризом, раз в месяц заходите в **Actions** и нажимайте **Run workflow** —
> или продублируйте пинг с компьютера (`install_ping.bat`) / через cron-job.org.

## Как бот хранит данные

У бесплатного Render файловая система контейнера **стирается при каждом перезапуске**.
Поэтому бот:

1. раз в 30 минут делает снимок базы (пользователи, группы, ДЗ, настройки, журнал
   напоминаний), сжимает его и отправляет **закреплённым сообщением** в чат владельца;
2. при старте контейнера, если база пустая, ищет это закреплённое сообщение и
   восстанавливает базу целиком.

Проверить и запустить вручную: `/admin` → **💾 Копия базы**.
**Не удаляйте закреплённое сообщение в чате с ботом** — это резервная копия.

## Ограничения бесплатного тарифа

| Ограничение | Как обходится |
|---|---|
| Сервис засыпает после 15 минут без запросов | пинг из GitHub Actions каждые 5 минут (шаг 4) |
| 750 часов работы в месяц на аккаунт | круглосуточный месяц ≈ 730 часов; если поднять второй сервис — часы складываются, следите за лимитом |
| Файловая система стирается при перезапуске | копия базы в закреплённом сообщении (выше) |
| Сборка после каждого `git push` занимает 2–5 минут | нормально; в логе видно прогресс |
| Первый запрос после долгой паузы может ждать ~30 секунд | пинг решает; сообщения в такие моменты Telegram придержит и доставит позже |

## Обновление кода

```powershell
cd schedule-bot
git add -A
git commit -m "обновление бота"
git push
```

Render пересоберёт сервис автоматически (`autoDeploy: true`). База не потеряется: она
поднимется из последней копии в чате.

## Если что-то не так

| Симптом | Что делать |
|---|---|
| В логе Render `401 Unauthorized` | неверный `BOT_TOKEN` в переменных сервиса — поправьте и нажмите **Manual Deploy** |
| В логе `Conflict: terminated by other getUpdates request` | где-то запущена вторая копия бота (на ПК или VPS). Остановите её: `remove_autostart.bat`, `systemctl stop schedule-bot` |
| `/health` отдаёт 502 | сервис просыпается после сна — подождите минуту и повторите |
| Бот отвечает, но копий базы нет | не задан `OWNER_ID` или владелец не написал боту `/start`; проверьте `/whoami` и переменные Render |
| После перезапуска пропали ДЗ | не было ни одной копии базы: проверьте `logs` и закреплённое сообщение в чате владельца |
| В логе `API вернул не JSON` | вуз сменил ключ доступа к API расписания — инструкция в [../docs/API.md](../docs/API.md) |
